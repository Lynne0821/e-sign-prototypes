# AI 赋能产品工作流：从一句话需求到高保真原型上线

**分享人**：业务产品经理
**面向对象**：全体产品经理 (PM)
**核心主旨**：如何利用 Cursor AI 及内置 Skills，将杂乱的业务资料快速转化为标准 PRD、流程图，甚至可交互的 HTML 原型，并一键生成在线演示链接。

---

## 🌟 背景与痛点

在日常的产品工作中，我们经常面临以下场景：
1. 业务方丢来一份 Excel 模板或几句零散的聊天记录，要求“做个对接”。
2. 画流程图、写 PRD 状态机耗时耗力，容易遗漏边界异常。
3. 拿着线框图和业务线确认需求时，缺乏交互感，沟通成本高。
4. 频繁修改文案或状态逻辑（如“联系人”改“签署人”），牵一发而动全身。

**解决方案**：引入 **AI 自动化工作流 (AI Workflow)**。结合我们最近落地的【采购/对账单 e签宝对接】项目，我总结了一套极速复用的 AI 技能链（Skills Chain）。

## 🛠️ 核心步骤与 Skill 拆解（建议收藏）

### Step 1：业务资料去噪与结构化解析
当拿到一堆杂乱的原始资料（如 Excel 模板、会议纪要）时，不要急着写需求，先让 AI 帮你梳理业务骨架。

*   **🎯 对应 Skill**：`erp-business-material-parsing`
*   **💡 触发关键词**：“帮我解析一下业务资料”、“原始需求整理”、“解析会议记录”
*   **💬 话术示例**：*“现在是业务原来在携客云管理的采购单，需要对接到交付系统发起 e签宝签署。这是现有的 Excel 模板，帮我解析一下以上业务资料。”*
*   **✨ 产出价值**：自动输出 `01_Parsing.md`，包含核心背景、用户画像、领域锚点（关键字段/限制）以及**疑点与模糊项（直接帮你列出需要去和业务方确认的问题清单）**。

### Step 2：需求识别与影响面分析
在确认了基础背景后，将事实转化为可落地的功能模型，并评估对现有系统的冲击。

*   **🎯 对应 Skill**：`erp-requirement-analysis`
*   **💡 触发关键词**：“需求识别”、“影响面分析”、“逻辑闭环”、“风险梳理”
*   **💬 话术示例**：*“补充业务规则：模板数据从上游对接，签署人系统自动匹配。基于以上，进行需求识别与影响面分析。”*
*   **✨ 产出价值**：自动输出 `02_RequirementAnalysis.md`，包含标准 User Stories、P0/P1 功能清单、业务规则、边界异常（Edge Cases）以及跨模块的风险评估。

### Step 3：核心流程可视化设计
用自然语言描述流程，让 AI 直接生成标准 Mermaid 图表代码，随时可修改。

*   **🎯 对应 Skill**：`mermaid-zh-flowchart`
*   **💡 触发关键词**：“核心流程设计”、“画个流程图”、“时序图”、“状态机”
*   **💬 话术示例**：*“跳过竞品分析，直接进行核心流程设计，包含泳道图、系统交互时序图和状态机。”*
*   **✨ 产出价值**：自动输出 `03_CoreProcessDesign.md`，生成高颜值的跨职能泳道图、API 时序图和状态流转图。

### Step 4：标准 PRD 文档合并生成
前置物料准备齐全后，一键组装成研发可读的标准 PRD。

*   **🎯 对应 Skill**：`erp-prd-generator`
*   **💡 触发关键词**：“合并生成 PRD 文档”、“写 PRD”、“生成需求文档”
*   **💬 话术示例**：*“基于以上解析和流程图，合并生成一份完整的 PRD 文档。”*
*   **✨ 产出价值**：自动输出 `05_e签宝对接PRD.md`，严格按照 ERP 后台标准，包含版本记录、字段表、搜索查询说明、状态机矩阵、按钮操作描述及上线准备事项。**（AI 会严格基于前文生成，不会凭空捏造字段）**。

### Step 5：高保真原型生成与在线发布
这是最惊艳的一步！不需要打开 Axure/Figma，直接让 AI 根据 PRD 生成带 Tailwind CSS 的高保真 HTML，并部署上线。

*   **🎯 对应 Skill**：`ui-html-from-screenshot` / 内置前端代码能力
*   **💡 触发关键词**：“生成菜单页面和必要的交互，输出 HTML 格式”、“把原型发布到 git，并生成访问链接”
*   **💬 话术示例**：
    1. *“基于以上 PRD，生成采购订单和对账单签署管理的菜单页面和交互，输出 HTML 格式。”*
    2. *“把‘联系人’改为‘签署人’，增加三个页面之间的相互跳转交互。”*
    3. *“帮我把原型发布到 git，并生成访问链接。”*
*   **✨ 产出价值**：获得极其逼真的前端页面（带 Tab 切换、弹窗、状态变色拦截等交互），并通过 GitHub Pages 生成公网链接，直接丢给业务和研发体验！

## 💡 PM 进阶 Prompt 技巧（避坑指南）

在本次【e签宝对接】实战中，我们总结了几个让 AI 更听话的技巧：

1. **分步投喂，不要一口吃成胖子**：
   *❌ 错误示范*：“给你个模板，帮我写个对接 e签宝的 PRD 并画出原型。”
   *✅ 正确示范*：先用 `解析业务资料` 梳理现状 -> 补充业务规则做 `需求分析` -> `生成流程图` -> `合并 PRD` -> `写 HTML 原型`。
2. **利用 AI 做全局批量重构**：
   *场景*：业务方突然说“联系人”这个词不专业，要改成“签署人”；“确认”状态要改成“已确认”。
   *操作*：直接对 AI 说：*“把所有文档和原型代码里的‘联系人’改为‘签署人’，‘确认’改为‘已确认’”*。AI 会在几秒内遍历所有 Markdown 和 HTML 文件完成精准替换。
3. **用自然语言调整交互逻辑**：
   *场景*：发现自动发起签署的逻辑有漏洞。
   *操作*：直接对 AI 说：*“签署状态的流转改一下，如果配置和上游状态满足则自动发起，如果配置异常则拦截并提示人工介入。”* AI 会自动重写 PRD 状态机，并修改 HTML 原型中的按钮置灰逻辑和弹窗提示。
