# 跨境电商 ERP 业务资料解析：采购单与对账单 e签宝对接

## 1. 核心背景 (Business Context)
- **业务背景**：原本在“携客云”系统中管理的采购订单和对账单，现需对接到公司的“交付系统”。
- **核心业务痛点**：目前单据可能缺乏高效、合规的线上签署闭环，或者跨系统流转存在断层。
- **期望业务目标**：实现采购订单和对账单在交付系统中直接发起**e签宝电子签署**，完成企业间（采购方与供应商）单据盖章流程的线上化与自动化。

## 2. 用户画像与角色 (Personas & Roles)
- **内部操作员（采购/财务）**：
  - **采购员**：负责在交付系统中查看从金蝶拉取的已审核采购订单，发起采购订单的 e签宝签署流程。
  - **财务/结算专员（如：张礼玲）**：负责查看从携客云拉取的已确认对账单，发起对账单的签署流程。
- **外部供应商（如：深圳市创达鑫电子有限公司）**：接收并确认单据，通过 e签宝完成具有法律效力的电子印章加盖。签署人和联系方式由采购线下提供并在系统中配置。
- **外部系统角色（接口人）**：
  - **金蝶ERP**：上游系统，提供状态为“已审核”的采购单原始数据。
  - **携客云**：上游系统，提供状态为“已确认”的对账单原始数据。
  - **e签宝服务**：负责模板渲染或组装后的PDF文件签署，提供电子印章、签署人管控和合同签发能力。

## 3. 业务流程与场景 (Process & Scenarios)
1. **数据拉取**：交付系统通过接口，定时或手动从“金蝶”拉取状态为`已审核`的采购单，从“携客云”拉取状态为`已确认`的对账单。
2. **单据组装生成**：交付系统根据拉取到的原始数据，自行组装成模板样式文件（参考现有的 Excel 模板格式转化为 PDF）。
3. **系统自动匹配签署人**：系统根据单据信息和默认配置，匹配到对应的内部签署组织信息以及供应商的签署人联系方式。
4. **内部确认与发起**：内部操作员确认单据无误后，点击“发起签署”。
5. **调用 e签宝接口**：交付系统将组装好的单据文件以及签署方信息推送至 e签宝，创建签署任务。
6. **e签宝平台内管控**：后续签署和用印管控（含审批流等）全部在 e签宝平台端内管理和完成，供应商也会收到 e签宝发出的签署通知进行签署。
7. **状态回传与归档**：e签宝通过 Webhook 将签署完成状态及已生效的文件回传至交付系统，更新单据状态为“已签署”并留档。

## 4. 领域细节锚点 (Domain Anchors) — 重点
- **关键数据 (采购单)**：
  - 抬头与主体：单据编号、采购日期、付款条件。
  - 明细行：物料编码、规格型号、采购数量、**含税单价**、**价税合计**、交货日期。
  - 汇总：数量合计、价税合计汇总。
  - 强制业务条款：逾期交货罚订货总金额 0.1%，未经书面同意 ECN 变更的退货担责等。
- **关键数据 (对账单)**：
  - 资金账户维度：出货含税/未税金额、退货含税/未税金额、费用含税/未税金额。**对账含税金额**必须等于“出货 - 退货 + 费用”。
  - 业务辅助：**截止发起日期已开票未付金额**、**截止发起日期已对账未开票金额**，关联开票与打款状态。
  - 明细追溯：包含“送货明细”（送货单号、入库单号、入库数量/单价）和“仓退明细”（退货单号、退货数量）。
- **技术现状与接口依赖**：
  - “金蝶”采购单（已审核状态）接口已就绪。
  - “携客云”对账单（已确认状态）接口已就绪。
- **业务限制**：采购订单条款第一条明确“传真件、扫描件、邮件均视为有效合同”，接入 e签宝后，需变更为“经 e签宝电子签章的电子文本具备同等法律效力”。

## 5. 疑点与模糊项 (Ambiguities)
- **已解决**：
  - 模板生成方式：交付系统自行组装样式文件发给e签宝。
  - 内部用印审批流：签署和用印管控在 e签宝平台管理。
  - 供应商实名与联系方式：采购会提供并在交付系统中配置，通过默认配置匹配。
- **待进一步澄清项**：
  - 如果金蝶或携客云的原单据发生变更（例如金蝶已审核的订单被反审核并修改），交付系统和 e签宝的作废/撤回机制是怎样的？
  - e签宝回调的 PDF 文件是否需要同步回传给金蝶或携客云？
